## Required transaction contract

A genuine user operation must supersede a waiting goal inside the original run/thread-operation admission transaction. The early thread mutation check is a separate transaction and must not commit a generation change before admission succeeds. Locks follow the original goal advisory/ordered tasks, then thread/binding, with existing execution/job/node lock ordering preserved. One active task per user/thread means a new user generation reuses the owned task; historical links and waiting groups retain their immutable identities.

The old waiting parent must have an accepted source and matching STOP/release evidence. New-generation admission stops automatic continuation from the old generation. Awaited cancellation uses exact immutable task/generation/parent/user/thread links and the original locked cancellation implementation; detached jobs remain independent. Stable owned operation receipts make repeated requests idempotent and prevent a stale cancellation from targeting a newer generation.

If continuation won admission first, an unassigned execution is cancelled through the original control path. An assigned execution keeps its original generation/current run until matching STOP/release, allowing original STOP/reconciliation checks to succeed. Unknown or unconfirmed work remains charged and blocks conflicting writers. Core terminal status or an expired lease is not proof of release.

Explicit user continuation may incorporate accepted old child results without resubmitting jobs. It needs a new trusted admission/source receipt, exact accepted workspace/checkpoint identity and the original bounded untrusted result summary. It must retain newer user messages and cannot rewind an older checkpoint merely to satisfy source checks. The existing paused Command.resume and automatic dispatched-group rules retain their original scope.

Human supersession authority comes from a trusted host entry point. Client metadata/context cannot grant it. Ordinary MCP notifications and scheduler launches retain their own admission behavior and cannot obtain human authority; trusted IM messages from a person retain the corresponding user-operation semantics.
