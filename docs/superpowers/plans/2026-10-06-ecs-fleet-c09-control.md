## Root authoritative decisions

1. The old high-level `pause task + increment generation` comment is superseded. Requesting cancellation does not change generation/current_run_id/active_attempt or release reservation. A fresh generation follows physical stop plus accepted recovery point in the original admission transaction.
2. Existing public interrupt and rollback retain distinct semantics. Interrupt stops the current run and yields paused recovery authority if a valid exact point can be accepted; task.cancel_requested_at is not a run-stop marker. No new whole-task/linked-job cancellation API is introduced here.
3. Rollback preserves the existing promise to restore the pre-run checkpoint. It does not invent filesystem rollback: Local rollback leaves files in place. Remote rollback must pair the actually restored checkpoint with the actually quiescent workspace at the same boundary; fail closed if that actual pair cannot be verified. The audit's suggestion to restore pre-run files is a proposal requiring source-contract evidence, not an additional requirement.
4. First winning run.cancel_requested_at plus120s, clipped to original task/attempt/frozen spec deadlines and any earlier local cleanup deadline, is immutable across duplicate requests and restart. Lease refresh never revives expired ownership or grants ordinary writes after intent.
5. Private cleanup authority is bound to original task/run/generation/attempt/node session/token/spec and explicit operations; no serialized boolean or public LaunchSpec grants it. Deny ordinary checkpoint/store/memory/extension/metadata/event/tool launch after intent. Allow only trusted cancellation normalization, exact terminal pair and same-outcome terminal tails, and physical owner settlement. A denied/unsettled owner results in retained recovery_required after stop, never a broader whitelist.
6. Original AgentRunner owns both actual executor Task and private observer Task and joins them through the same retained cleanup lifecycle. record.task must reference the actual run_agent executor; a bare abort_event is insufficient for a blocked tool. No shadow RunManager or second graph loop.
7. Node agent renewal cooperates only during the original bounded cleanup window. Hard stop remains required on authority loss/deadline/failed cleanup. B job renewal/stop behavior remains unchanged. END and core terminal are not physical stop proof; wait=true returns204 only after durable originalattempt.stopped_at, otherwise202 pending or the existing conflict semantics.
8. Paused/input_required resume reuses the same Agent task and atomically increments generation/binds a new run after accepted pair+physical stop+released reservation. No standalone current_run_id clear, no global relaxation of paused thread guards, no new-session bypass. Preserve existing C08 branch/completed-new-turn semantics.

## Design decisions proposed to Root

- Stop-current-run interrupt is persistent core run cancellation intent, not whole Agent task cancellation. Do not set task.cancel_requested_at for this operation; that field remains terminal task-cancel intent. No new BC linked-job feature or public task cancel entry is needed when no original public entry exists.
- Gateway host-owned `AgentRunControl` adapter (`backend/app/fleet/agent_control.py`) handles remote run identification, owner scoped atomic request, read-only stop observation. RunManager uses an injected neutral adapter before Local cancel logic; harness imports no app/Fleet. Install alongside fleet ownership. Adapter returns first-winning action and existing outcome; it never terminalizes a started attempt or releases reservation.
- Cancellation TX uses existing shared order task→run→placement→node→reservation→attempt and fresh DB time. Keep generation/current_run_id/active_attempt/ownership/token/session/resource charges unchanged. Record first run.cancel_action and first run.cancel_requested_at. Deadline is computed as min(first_requested_at+120s, task.deadline, attempt.execution_deadline, frozen spec.execution_deadline); no schema field is necessary for this deterministic restart-stable bound. Renew leases only until this bound and only before the existing original lease expires: cancellation does not resurrect expired ownership. Existing earlier local CleanupBudget still wins. A DB deadline plus original local monotonic clamp must account for request RTT/send-time, never add response latency.
- Bind `private_cancel_observer` through original AgentEnvironment, provided by runner_context; it reads original durable identity/control through short bounded queries and owns no write capability. AgentRunner retains one observer Task alongside original run_agent Task, associates record.task, signals process-only abort through neutral RunManager entry (safe wrapper of `_signal_local_cancel`), and enters host-controlled cancellation cleanup policy before original finally work. Observer task has strong ownership and is joined in the original cleanup budget on every exit; cancellation, query failure and identity loss cannot leave an escaped task. No shadow runner or runner HTTP service.
- On Agent renew, return cooperative cancellation action and bounded remaining-cleanup seconds under exact identity rather than immediate hard stop; Node keeps a short original lease/watchdog while actual Runner observes SQL intent. This is observation/stop coordination, not authority. B renew branch unchanged. Identity/auth errors, execution limit, cleanup deadline or failed cooperative handling hard-stop via existing managed container driver; physical stop ACK is still required. Node must continue serving only an exact cancellation-final workspace request while cooperative cleanup is live.
- Ordinary checkpoint/store/memory/extension/events/metadata/tool launch rights cease immediately on intent. A private host cleanup scope authorizes only exact original-run cancellation bookkeeping, graph settlement (rollback/discard inflight writers, no new work), trusted title and rollback checkpoint normalization, exact paused/final publication/accept, same-outcome terminal tails, original service/MCP/process drain. Scope and operations are nonserializable private capability, bound to original identity and unchanged generation; boolean allow_terminal alone is insufficient. Do not add memory/store/extension/general events writes to cleanup whitelist. Operations that cannot settle under this restriction lead to physical stop plus recovery_required, not weakened fences.
- Success preparation can exist when cancellation wins; only read-only observation of winning action is allowed, then original host discards stale prepared success, settles once, makes a fresh interrupted cancellation root/descriptor and CAS-pairs it. Completion commits first => cancel cannot alter immutable point/core outcome, though wait=true should still observe stop if that route is accepted. Cancellation commits first => success cannot commit or send success END. Both use same row-lock order and same-session terminal point insertion.
- Public wait=true returns 204 only after original attempt physical stopped_at is durable (and expected managed identity is verified); stream END/core terminal is insufficient. Use bounded read-only waiting, request disconnect handling; timeout/unconfirmed returns existing 202 pending behavior, never 204. wait=false stays 202. Repeated remote cancellation stays first-winner and stable even after cache restart; decide explicit already-completed HTTP conflict policy consistent with Local contract.
- User stop-current-run always produces interrupted / task paused exact point, even if snapshot.next is empty; artificial current-run stop must not be inferred from historical human cards. Original graph human interrupt produces input_required when real current-run observation/pending interrupt indicates input, ordinary graph pause produces paused. Physical ACK applies these task states only after point acceptance.
- Resume uses new run ID and generation on same paused/input_required Agent task under original admission TX. Require exact accepted paused pair, original attempt physically stopped, reservation released, correct user/thread/binding/source/checkpoint, no unresolved attempt, currenttask not task-cancelled, deadline/budget valid. Only then atomically increment generation, replace current_run_id with newly admitted run, move task queued/create placement and frozen LaunchSpec. Retain old run/attempt/point history. Do not clear current_run_id in an independent session; do not relax all paused states globally in thread admission. C08 branch and completed-new-turn behavior retain existing checks.

Full rollback implementation is necessary after interrupt main, not a reason to delay first main.
- First cancellation deadline+120s clipped to original task/attempt/spec deadlines is no new durable schema. If operations require persisted pre-intent earlier cleanup start across host crash, current host cannot restart same attempt anyway; no new session rescue authority. Any schema need must be demonstrated, not invented.
- Pending memory/extension TX at cancellation must either settle before intent wins under existing TX lock/fence or roll back after intent. A broad drain permission for ordinary writes would violate the stated scope. Need explicit retained rollback evidence rather than granting normal memory write for 120s.
- Late-cancel CAS presently calls participant before discovering cancel. Design must expose read-only firstwinner observation without allowing stale success writes/descriptor acceptance; reprepare original interrupted point after winner observation and retain total budget.
- Original execution deadlines still clip cleanup; a near-timeout interrupt may necessarily lack a valid paused pair and become recovery_required after physical stop. Document honest pending/recovery behavior; do not extend lease/deadline by 120s beyond original bounds.
- Already-completed remote cancel HTTP response policy must match existing Local not_cancellable semantics while accepted outcome remains immutable. 204 never proves stop unless original durable stop was observed.

## Critical risks

Premature generation increment revokes original cleanup/STOP authentication. Extending renew without cancel-aware normal-write rejection grants ordinary writes. END/coreterminal incorrectly treated as stop releases thread too early. Joining escaped observer/service tasks outside first 120s resets budget. New-session recovery bypass makes two physical writers. Prepared success point reused for cancellation mispairs checkpoint/outcome. Remote rollback checkpoint-only restore loses file consistency. Broad paused admission relaxations regress C08 branches. Existing missing fleet_probe or stale image is setup failure, never business RED.
